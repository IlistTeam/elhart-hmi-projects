# Проекты ELHART HMI Soft

Целевая среда — **Windows с установленным ELHART HMI Soft 3.x**. Нативные
проверки используют Windows PowerShell 5.1/.NET Framework. XML-инструменты
на Python можно запускать отдельно на других ОС; это не подтверждает сборку HMI.

Создавай редактируемый нативный проект с действиями кнопок, цифровыми
значениями и полным набором состояний. Сохраняй выбранную пользователем
панель, процесс и внешний вид. Разделяй демо на внутренней памяти и управление
оборудованием: карта регистров и блокировки примера SLM не универсальны.

## Выбор основы

- Для правок сначала прочитай актуальный проект пользователя; работай с копией,
  сохраняя идентификаторы, адреса и действия, которые не требуется менять.
- Для нового проекта предпочтительны компоненты, сохранённые самой установленной
  версией Elhart. Полные нативные DTO копируй как прототипы, вместо сборки XML
  по памяти: необязательное для загрузчика поле может быть обязательным для сборщика.
- Для похожего демо извлеки `assets/slm-ecp10-starter.zip` командой
  `python scripts/project_tool.py starter --out <новая-папка> --name <имя>`.
  Это пример 1024×768 с пятью экранами и внутренней памятью, не пустой проект.
  Прочитай [пример SLM](references/slm-example.md) перед его использованием.
  Успешное извлечение архива не подтверждает его сборку. До расширения основы
  проверь системные настройки и, если доступен редактор, полностью собери копию
  в целевой версии Elhart; после адаптации повтори полную сборку.
- Версию, профиль панели и кодировку адресов проверяй по установленным
  каталогам. Известные значения для 3.0.15569 в [native-format.md](references/native-format.md)
  не распространяй на другую версию без проверки.

## Создание и изменение

Перед нативными изменениями прочитай [native-format.md](references/native-format.md):
правила состояний, числовых ограничений, геометрии, подписей и XML.

Сначала зафиксируй разрешение и компоновку: области цифр, единиц, значков,
подписей, кнопок и навигации. При смене пропорций перекомпонуй экран по смысловым
областям; круги, значки и шрифты сохраняй пропорциональными. Декорации могут быть
растровыми, но действия, значения и состояния должны оставаться нативными.
Концептуальные картинки создавай через доступный imagegen, если этого требует
задача; они не заменяют проект и снимки симулятора.

Для точечных XML-правок используй `scripts/native_xml.py`: он сохраняет области
префиксов QName и проверяет их перед записью. Команда
`python scripts/project_tool.py xml-check --project <папка>` проверяет QName
во всех нативных XML-файлах. Не сериализуй файлы простым ElementTree без
обработки QName в `i:type`: синтаксически верный XML может содержать неверный тип DTO.

Для интерактивного демо прочитай [demo-runtime.md](references/demo-runtime.md).
Период вызова макроса и время процесса — разные величины. Частые вызовы и
переключения экранов не должны ускорять таймеры или стирать команды.

## Проверка до передачи

Используй [verification.md](references/verification.md) для команд и их границ.

1. `project_tool.py xml-check` и `validate_native.ps1`: все окна, включая
   DropDown, Keyboard и системные; библиотеки, макросы и конфигурации `HMI/System`,
   особенно `GlobalConfigInfo.cfg` и `ExtendedPropertyInfo.cfg`. Отдельно сверь
   профиль панели с установленным каталогом.
2. Проверь модели, состояния, ограничения и геометрию, затронутые изменением.
   Десериализация DTO не доказывает успешную компиляцию.
3. При изменении логики собери макрос для симулятора и архитектуры панели,
   проверь поведение и время. Для SLM есть отдельный комплект тестов.
4. Полная компиляция в Elhart, включая системные настройки, и новый симулятор: переходы, кнопки, значения,
   состояния, видимость, отступы и время процесса.

При ошибке «Настройки системы → Общие настройки» следуй разделу
[диагностики системных настроек](references/verification.md#ошибка-сборки-общих-настроек).
Не приписывай её адресу часов или другому полю без воспроизведения причины.

При ошибке настройки кнопки и красной отметке «Настройки управления» проверь
[порядок полей ControlSettingsProperty](references/verification.md#ошибка-настроек-управления-кнопки).
XML-загрузчик может успешно завершиться, молча пропустив настройки после поля
с неверным DataMember.Order; сверяй загруженные условия и вызовы макросов.

Управляй приложением через доступный навык computer-use. Если захват окна
не работает, после одной повторной попытки с новым дескриптором продолжи
файловые проверки и отметь непроверенные компиляцию/симулятор. Не нажимай
по старым координатам и не выдавай рендер геометрии за снимок приложения.

Передавай `.fsprj` вместе с каталогами HMI и Global и при необходимости архивом.
Дай ссылку на актуальную версию и кратко сообщи, что проверено. Не обещай
безошибочность без сборки и симулятора целевой версии.
При известной ошибке компиляции результат остаётся неисправным; исправь её
и повтори сборку до объявления проекта готовым. Если полная сборка недоступна,
передавай результат с явным статусом «полная сборка HMI не подтверждена».
